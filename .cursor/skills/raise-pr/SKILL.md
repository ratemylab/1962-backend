# Raise a pull request (GitHub)

## Goal

Open a PR with a **semantic title**, **accurate body** grounded in the actual diff and file reads, **labels** from project config, and **assignee** `@me`. Follow [Conventional Commits](https://www.conventionalcommits.org/) for the title.

## Prerequisites

- `git` and [GitHub CLI](https://cli.github.com/) (`gh`) authenticated (`gh auth status`).
- Resolve and persist git metadata per [references/git-config.md](references/git-config.md) using **`CURSOR.md`** at the repo root.

## Steps

### 1. Git config

Read the **Git Config** table from `CURSOR.md`. For any empty field, resolve and update `CURSOR.md` as described in [references/git-config.md](references/git-config.md).

### 2. Gather branch context (run in parallel)

Let `<base>` be the configured base branch.

- `git branch --show-current`
- `git log <base>..HEAD --oneline`
- `git diff <base>...HEAD --stat`
- `git diff <base>...HEAD` — use the full diff to scope follow-up reads

### 3. Read changed files

Open **every file touched** in the diff (not only stat). The PR description must reflect **what the code does**, not guesses. If a change is binary or generated and not meaningful to quote, say so briefly under **Changes**.

### 4. AI / tool attribution check

In all changed files, search for markers such as: `Generated by`, `Co-Authored-By:` (especially AI tools), `AI-generated`, `CURSOR`, `ChatGPT`, `Copilot`, `Cursor` (when used as attribution), and similar. If any are found, **list locations and stop**. Do not open the PR until the user removes them from code and commits.

### 5. Write the PR

- **Title**: `<type>(<scope>): <description>` — under **70** characters, imperative, Conventional Commits.
- **Body**: Follow [references/pr-body.md](references/pr-body.md). **Summary** and **Changes** must match what you read in the diff and files.
- **Labels**: Choose zero or more from the comma-separated list in `CURSOR.md`. Skip labels if none fit or the list is empty.

**Rules**: No AI citations or filler in title or body. Do not invent behavior you did not see in the code.

### 6. Create the PR

Prefer **`--body-file`** to avoid shell-escaping issues:

```bash
# Write the body to a temp file, then:
gh pr create \
  --base "<base_branch>" \
  --title "<title>" \
  --body-file /path/to/body.md \
  --assignee @me
```

Add labels with repeated flags (adjust for your `gh` version if needed):

```bash
gh pr create ... --label "label1" --label "label2"
```

If the CLI accepts a single comma-separated `--label` in your environment, that is acceptable. Omit `--label` when not using labels.

## Rules summary

| Rule | Detail |
|------|--------|
| Base branch | From `CURSOR.md` Git Config table (see [references/git-config.md](references/git-config.md)) |
| Assignee | `--assignee @me` |
| Title | Conventional Commits; no AI attribution |
| Content | Based on diff + file reads only |
| Blockers | AI/tool citation strings in changed files |
